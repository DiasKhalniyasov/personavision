# The committed calibration corpus

Four small records, generated by committed code, that every later ticket of step #11 tests against — so calibration
runs in CI in seconds with no download, no network and no API key.

## These records are synthetic, and a figure measured on them is not a UEyes score

This repository vendors **no UEyes bytes**: not an image, not a saliency map, not a scanpath. The
[README](../README.md#this-repository-vendors-no-dataset-bytes) gives the two reasons and the auto-decision on #11
settles it. So the committed corpus is a **synthetic stand-in**: solid rectangles and Gaussian blobs, written by
`scripts/make-corpus.ts`, shaped exactly as a converted UEyes record (#86) in the ground-truth types #81 declares.

Pointing the same metric, baseline or scoring code at the real downloaded dataset therefore changes the data and not
a line of the code — which is the whole point of the shape being identical.

It also means:

> **A figure measured on this corpus is not a published UEyes score.** It is a figure about four synthetic pictures.
> A number comparable to published work comes only from a local run against the downloaded dataset
> (`personavision calibrate score --dataset`, #91). Every report that quotes a corpus figure says so in its heading
> (#89), not in a footnote, and the product's badge never shows one.

What the corpus _is_ good for is the thing a benchmark figure cannot do: making a regression visible. If a change to
the engine lowers its score on these four records, something about the prediction changed, and the gate (#89) says
so in seconds.

## The records, and what each one exists to prove

Every record carries its image, the humans' aggregated saliency map, one scanpath per participant with each
fixation's dwell, its category, and the display the humans were shown it at. The names and the reasons are also on
`CORPUS_RECORD_NAMES` in [`../src/corpus.ts`](../src/corpus.ts), next to the code.

| Record                   | Category | Image     | Participants | Exists to prove                                                                                                                                                                 |
| ------------------------ | -------- | --------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `webpage-bright-hero`    | webpage  | 320 × 240 | 3            | One bright band on a flat field, with the human map and all three scanpaths on it: the case a working predictor must score well on. Its three participants agree in part and not in whole, so the human-to-human agreement ceiling (#84) is measurable on committed data. |
| `desktop-two-panels`     | desktop  | 320 × 240 | 2            | Two equally bright panels with equal map mass either side of the midline, and both participants visiting the left one before the right: the case an order-sensitive metric (#84) can see and a location-only metric (#83) cannot. |
| `mobile-single-fixation` | mobile   | 240 × 320 | 1            | The degenerate record: one participant, one fixation, cut at one second of viewing, at a 2× device scale factor. The edge case lives in the corpus and not only in a unit test.  |
| `poster-uniform-field`   | poster   | 320 × 240 | 2            | One flat colour and a map so broad it is nearly uniform: nothing should stand out, so an over-confident prediction scores badly and a metric has something to punish.            |

All four categories are present, and the `webpage` category — what this product is for — is never empty. The loader
returns one record by name (`loadCorpusRecord`), all the records of one category (`loadCorpusCategory`) or the whole
corpus (`loadCorpus`), and raises `CorpusError` on a name or a category it does not hold rather than returning
nothing.

### The two measured differences

`test/corpus.test.ts` asserts these from the committed bytes, because a metric ticket claiming "a confident
prediction is punished on a flat field" is only testing something if the field really is flat:

| Measure                                   | `webpage-bright-hero` | `poster-uniform-field` |
| ----------------------------------------- | --------------------- | ---------------------- |
| Mass in the ten heaviest cells (of 192)   | 0.59                  | 0.065                  |
| Heaviest cell ÷ mean cell (1 is flat)     | 15.0                  | 1.27                   |

The poster record is the flattest of the four by both measures, and the test asserts that too.

## The shape, cell by cell

- **Geometry is image space.** The origin is the image's top-left pixel, `x` runs right, `y` runs down —
  `src/types.ts` fixes this, and it is not the run artifact's page space.
- **A map is coarser than its image**: 20 image pixels to a cell, so a 320 × 240 image carries a 16 × 12 map of 192
  cells. The map's aspect ratio equals the image's, so a cell-for-cell comparison compares the same picture.
- **Normalisation is `sum-to-one`.** The generator writes each cell to twelve decimal places, which keeps the JSON
  compact and byte-identical across regeneration and moves the sum by at most a few hundred times 5 × 10⁻¹³. So the
  cells sum to one **to within 1 × 10⁻⁹**, which is the tolerance the test asserts. Every cell is finite and
  non-negative; a cell far from every blob rounds to exactly zero, which in ground truth is a cell the humans did
  not look at, not a missing value.
- **A fixation's `tMs`** runs forward from the first fixation at zero, with a 40 ms saccade between one fixation's
  end and the next one's onset. One value for the whole corpus: nothing here is a claim about saccade duration, it
  is what makes `tMs` ordered and consistent with `durationMs`. No scanpath runs past its stated viewing duration.
- **The display covers the image exactly**: `viewport × scale` equals the image size in every record, so a predictor
  that reads the display and one that reads the image agree. `mobile-single-fixation` has `scale: 2`, so the field
  is exercised rather than assumed to be 1.
- **`imagePath` is not committed.** It is absolute and machine-specific, so the JSON holds the record without it and
  the loader fills it in from `CORPUS_DIR`.

## Regenerating it

```sh
pnpm -F @personavision/calibration corpus
```

The generator is deterministic — solid rectangles painted into a raw buffer, Gaussian blobs evaluated in closed
form, PNG options set explicitly, no fonts, no randomness, no timestamps — so this rewrites every committed byte and
the working tree stays clean. `test/corpus.test.ts` asserts that the committed files really are its output, both the
JSON and the image, so the claim is checked rather than documented.

## The byte budget

Every later session in this step reads these files, so they are small and stay small:

| Record                   | Image   | Ground truth |
| ------------------------ | ------- | ------------ |
| `webpage-bright-hero`    | 755 B   | 5,334 B      |
| `desktop-two-panels`     | 870 B   | 5,596 B      |
| `mobile-single-fixation` | 778 B   | 3,957 B      |
| `poster-uniform-field`   | 600 B   | 5,459 B      |
| **Total**                |         | **23,349 B** |

**The budget is 32 KiB (32,768 B)** for the corpus as a whole, asserted by `test/corpus.test.ts`. A record added
beyond that budget is a decision to make deliberately, by raising the number in the test and in this table, not by
noticing the repository has grown.
